# Learning Loop Policy

## Purpose

Nova Money Scout must improve from repeated attempts.

The system should not merely run tasks. It must learn from:

- Chris Boost/Bury votes
- source-review decisions
- audit warnings
- artifact quality
- repeated market signals
- future spend results
- future revenue results
- failed assumptions
- repeated errors
- successful patterns

## Core Rule

Learning must be evidence-based.

Nova must not claim that an idea works, sells, converts, or has ROI unless the system has measured evidence.

## What Counts As Learning Evidence

- Chris clicked Boost +1
- Chris clicked Bury -1
- an artifact was created
- an artifact was revised
- a source was repaired
- enterprise audit warned or failed
- a source signal repeated across multiple feeds
- a local test produced measurable engagement
- a future paid test produced spend/revenue/profit data
- an idea was parked and later revived by new evidence

## What Does Not Count As Learning Evidence

- vibes
- AI confidence alone
- a single catchy title
- unverified claims
- assumed buyer demand
- assumed revenue
- assumed legal/compliance certainty

## Learning Actions

When something works:

- preserve the pattern
- increase local priority
- improve related artifacts
- search for adjacent opportunities
- prepare a stronger review packet

When something fails:

- record the failure
- lower priority
- tighten filters
- avoid repeating the same weak pattern
- preserve it for dedupe memory

When something is unclear:

- keep it source_review_required
- request more evidence
- avoid promotion
- do not spend money

## Budget Learning

Future budget must follow ROI.

- winners can receive cautious increases
- losers must stop, revise, or be buried
- unknowns get tiny tests only
- spending increases require proof
