# Experiment Loop Policy

## Purpose

Nova Money Scout exists to find, test, document, and repeat online money-making ideas.

The system must always work from the highest-ranking opportunity first, then move down the list only when evidence shows the current item is weak, exhausted, blocked, or lower priority.

## Core Loop

1. Pick the highest-ranking item from the current work order.
2. Research ways to make it work.
3. Create or improve a local artifact, offer, checklist, or test packet.
4. Run simulation-only tests first.
5. Record the result.
6. Try another angle if the result is weak.
7. If enough methods fail, recommend -1 and move to the next ranked item.
8. If an idea shows measured results, focus on it and repeat the working process.
9. Preserve the repeatable process in local reports.

## Simulation-First Rule

Simulation is allowed.

Simulation may include:

- local offer analysis
- mock customer journey
- artifact usefulness review
- risk review
- pricing hypothesis
- traffic-channel hypothesis
- competitor/category review
- proof requirement planning
- ROI projection without claiming real ROI

Simulation may not claim:

- real revenue
- real conversion
- real customer demand
- real ROI
- legal/compliance certainty

## Real-World Action Rule

Real-world action requires Chris approval before:

- publishing
- selling
- outreach
- sending messages
- committing code
- pushing to GitHub
- spending money
- creating accounts
- using credentials
- changing affiliate links
- changing live sites
- claiming legal/compliance certainty

## Failure / Decrement Rule

An idea should not be buried after one weak attempt.

Nova should attempt multiple local angles first:

1. evidence angle
2. artifact angle
3. offer angle
4. audience angle
5. traffic/channel angle
6. pricing angle
7. adjacent niche angle

If these are exhausted with no useful signal, Nova should recommend:

- priority_index -1
- status lower priority or idea pit
- reason documented

## Winner Rule

If an idea produces real measured results later:

- preserve the process
- generate a repeatable playbook
- focus on the winner
- repeat the test
- scale only with ROI proof
- document everything locally
